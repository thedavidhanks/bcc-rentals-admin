## 2. Task specs

### P6.3 — Update Prices (`code-writer`, worktree, `requireScheduler`)

CRUD `item_prices` for any item with **§6 validation**:

- `price_cents >= 0` (integer cents — no floats).
- Time = **minutes since local midnight, `America/New_York`**: `start_minute`/`end_minute` in
  0–1440, **both-null-or-both-set**, `end > start`. `days_of_week` = `smallint[]`, `0=Sun..6=Sat`,
  `null` = every day. Respect the existing check constraints (§4).
- **Warn** if an edit/delete would leave the item with **no all-days/all-hours base row** (the
  storefront needs a base rate to fall back to). Warn — don't silently block — per §6/§7.
- Show the **effective/base rate + overrides** per item (§7 Update Prices page, ~L379).
- Write `admin_audit_log` on **every** mutation (create/edit/delete) via `writeAuditLog`.

### P6.4 — Products admin (`code-writer`, worktree, `requireAdmin`)

- **Add:** all `items` fields **+ a base price** on the create form → writes the first
  all-days/all-hours `item_prices` row (via the existing item-prices repo — see the §1 seam note).
  Unique **URL-safe slug**; enforce every §4 check constraint.
- **Edit:** **deactivate, don't delete** (`active=false`); set **`updated_at = now()`** on every
  edit. Slug stays unique + URL-safe.
- Admin-only — `requireAdmin` on **every** mutating action (server-enforced, never UI-only).
- Write `admin_audit_log` on every mutation.

### P6.5 — Categories admin (`code-writer`, worktree, `requireAdmin`)

- CRUD `categories` (unique slug, name, `sort_order` — §6/§7 ~L319).
- Assign/unassign products to categories via `item_categories`.
- Admin-only — `requireAdmin` on every mutating action.
- Write `admin_audit_log` on every mutation.

## 3. Cross-cutting requirements (apply to all three)

- `import "server-only"` in any module touching the DB or secrets; mutations are Next.js server
  actions guarded by `requireScheduler`/`requireAdmin` (server-side, in **every** mutating path).
- **Audit every mutation** — `writeAuditLog` (P3.2 writer exists) with `action`, `entity`,
  `entity_id`, and before/after detail. This is non-negotiable per CLAUDE.md.
- Match storefront row shapes when reading/writing shared tables (`items`, `item_prices`,
  `categories`, `item_categories`); when unsure, mirror the repository shapes already in
  `lib/repositories/`.
- **No agent runs DDL or deploys.** These tasks need **no** schema change — the tables already
  exist on dev + prod. If an agent thinks it needs new DDL, that's a red flag: stop and surface it.
- Each `code-writer` hands its branch to `test-engineer` (launches as-is on its pinned
  `claude-sonnet-5` — no `model:` override) for verification
  before you integrate. Add/extend unit tests (mocked `pg`, matching the existing suite style):
  price validation boundaries (both-null/both-set, `end>start`, base-row warning), slug
  uniqueness/URL-safety, deactivate-not-delete, category assignment, and **server-side role
  denial** for the admin-only actions.
